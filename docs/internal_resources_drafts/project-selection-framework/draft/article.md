## Opening (replace with friction-led prose)

The wrong project is not lazy. It is polished, pretty, and impossible to talk about in an interview without bluffing.

## Portfolio value test (three questions)

- Can you describe a user or operator who benefits without hand-waving?
- Can you point to code or a demo when asked “show me”?
- Can you name what broke and what you changed?

## Scope ladder for first-years

- Tiny but complete vs ambitious but hollow.
- When a team project is a net plus vs a coordination trap.

## Tutorial anchoring done honestly

- Adding a constraint the tutorial did not have: minimum viable originality.
- **Your bullets:** examples you are willing to name.

## Kill criteria before you start

- If you cannot finish in N weeks with your real schedule, shrink scope now.

## One project in flight rule (optional discipline)

- When multitasking projects helps vs dilutes interview stories.
