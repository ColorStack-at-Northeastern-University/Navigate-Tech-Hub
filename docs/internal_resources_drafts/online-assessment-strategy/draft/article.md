# Online Assessment Strategy for Timed Screens

## Editor meta

- Silent-read word budget: about 900–1,100 words.
- Voice: `.cursor/rules/navigate-writing.mdc`.
- Volatility **medium**: vendor platforms change UI and rules; avoid “always works” claims.

## Opening (replace with friction-led prose)

Timed screens punish perfectionism. They reward triage under pressure.

## Know the format before you click Start

- Typical shapes: MCQ, coding, mixed. What to verify in the email or portal first.
- Environment checks: scratch paper, second monitor rules, IDE policy ([FACT CHECK: per platform]).

## First five minutes: read everything

- Point budgets per section if shown.
- Where partial credit actually exists vs where it does not.

## Triage algorithm

- Skip-stub-return vs grind-one-perfect: when each wins.
- Flagging a problem for revisit: literal bookmark habit.

## Pacing markers

- Halfway clock check: what to do if you are behind.
- Last ten minutes: tests vs edge cases vs cleanup.

## Common failure modes

- Over-engineering the easy problem.
- Silent panic when the first problem is ugly.

## After the screen

- What feedback you can reasonably expect (often none).
- When a polite follow-up is OK vs spammy.
